# Database / Spreadsheet Schema — Sistem Absensi & Penilaian Siswa SD (Versi 2)

## 1. Konvensi penyimpanan
Database menggunakan Google Spreadsheet. Setiap tabel di bawah adalah satu sheet dengan nama sheet persis seperti judul `Sheet`. Baris pertama berisi header persis sesuai urutan kolom. ID menggunakan string UUID atau ID unik yang stabil (direkomendasikan UUID) karena Google Sheets tidak memiliki auto-increment transaksional yang aman. Jangan menggunakan nomor baris sebagai ID.

Kolom audit umum: `id`, `created_at`, `updated_at`. Timestamp disimpan dalam format ISO 8601 atau Date yang konsisten. Tanggal akademik disimpan sebagai tanggal yang konsisten dan ditampilkan dengan format Indonesia.

`setup.gs` wajib:
- meminta atau menggunakan Spreadsheet target yang eksplisit dan dapat diverifikasi;
- membuat sheet yang belum ada;
- menambahkan header hanya pada sheet baru/kosong;
- jika header sudah ada, memvalidasi kecocokan nama dan urutan kolom;
- tidak menghapus, mengosongkan, mengganti nama, atau menimpa data yang sudah ada secara otomatis;
- menghentikan proses dengan pesan yang jelas jika ditemukan header tidak cocok;
- aman dijalankan berulang kali (idempotent);
- menyiapkan data pengaturan awal hanya jika belum ada, dengan pemeriksaan sebelum insert;
- memisahkan inisialisasi akun kepala sekolah dari setup skema, dan tidak membuat kredensial default permanen secara diam-diam.

## 2. Relasi dan aturan penting
- `user.id` direferensikan oleh `wali_kelas.user_id`.
- `tahun_ajaran.id` direferensikan oleh `wali_kelas.tahun_ajaran_id` dan `pengaturan_rapor.tahun_ajaran_id`.
- `wali_kelas.id` menjadi identitas penugasan seorang user untuk kelas pada periode tertentu, direferensikan oleh `siswa.wali_kelas_id`, `mata_pelajaran.wali_kelas_id`, dan `pengaturan_rapor.wali_kelas_id`.
- `siswa.id` direferensikan oleh `nilai_mata_pelajaran.siswa_id`, `nilai_sikap.siswa_id`, dan `rekap_kehadiran.siswa_id`.
- `mata_pelajaran.id` direferensikan oleh `nilai_mata_pelajaran.mata_pelajaran_id`.
- Nilai harus merujuk siswa dan mata pelajaran dari penugasan/tahun ajaran yang sama. Backend wajib memvalidasi relasi lintas sheet.
- `wali_kelas` merupakan tabel penugasan, bukan hanya daftar guru. Satu user dapat memiliki penugasan historis berbeda pada tahun ajaran berbeda, tetapi tidak boleh memiliki dua penugasan aktif untuk kelas yang sama dalam periode yang sama.
- Satu kelas hanya 1–6, tanpa kelas paralel.

## 3. Skema sheet

### 3.1 Sheet `user`
| Kolom | Tipe/logika | Aturan |
|---|---|---|
| id | string | PK unik |
| nama | string | wajib |
| nip | string | opsional; jika diisi harus unik |
| username | string | wajib, unik, dinormalisasi trim |
| password_hash | string | wajib; hash, bukan password mentah |
| password_salt | string | wajib jika strategi hash memerlukan salt tersimpan |
| role | enum | `kepala_sekolah` / `wali_kelas` |
| foto | string | opsional, ID/referensi file Drive |
| terakhir_login | datetime | boleh kosong |
| is_active | boolean | default true; akun nonaktif tidak bisa login |
| created_at | datetime | audit |
| updated_at | datetime | audit |

Catatan: pengguna menyebut kolom `password`; implementasi wajib menggunakan `password_hash` (dan salt bila diperlukan) untuk menghindari penyimpanan password plaintext. Jangan menambahkan kolom `password` plaintext.

### 3.2 Sheet `tahun_ajaran`
| Kolom | Tipe/logika | Aturan |
|---|---|---|
| id | string | PK |
| tahun_ajaran | string | format mis. `2026/2027` |
| semester | enum | `Ganjil` / `Genap` |
| tanggal_mulai | date | wajib |
| tanggal_selesai | date | wajib, setelah tanggal mulai |
| is_active | boolean | maksimal satu periode aktif |
| is_locked | boolean | true ketika periode telah ditutup; data historis baca-saja |
| created_at | datetime | audit |
| updated_at | datetime | audit |

Kombinasi `tahun_ajaran + semester` harus unik. Setelah periode ditutup, penugasan, data siswa, mata pelajaran, nilai, dan pengaturan pada periode itu tidak boleh diedit oleh wali kelas. Kepala sekolah boleh melihat data historis; perubahan historis harus dibatasi dan tidak dilakukan lewat alur normal MVP.

### 3.3 Sheet `wali_kelas`
| Kolom | Tipe/logika | Aturan |
|---|---|---|
| id | string | PK penugasan |
| user_id | string | FK ke `user.id`, role harus wali_kelas |
| tahun_ajaran_id | string | FK ke `tahun_ajaran.id` |
| kelas | enum/string | salah satu `1`, `2`, `3`, `4`, `5`, `6` |
| is_active | boolean | status penugasan |
| created_at | datetime | audit |
| updated_at | datetime | audit |

Kombinasi `tahun_ajaran_id + kelas` unik untuk mencegah dua wali kelas pada kelas/periode yang sama. User yang sama boleh mempunyai penugasan pada periode berbeda. Kepala sekolah memilih user, tahun ajaran, dan kelas ketika membuat penugasan.

### 3.4 Sheet `siswa`
| Kolom | Tipe/logika | Aturan |
|---|---|---|
| id | string | PK |
| wali_kelas_id | string | FK ke penugasan `wali_kelas.id` |
| nisn | string | opsional sesuai kebijakan sekolah; jika diisi unik dalam data sekolah |
| nis | string | opsional; jika diisi unik dalam data sekolah |
| no_absen | number | wajib, bilangan positif; unik dalam satu penugasan |
| nama | string | wajib |
| jenis_kelamin | enum | `L` / `P` |
| tempat_lahir | string | opsional |
| tanggal_lahir | date | opsional |
| wali_murid | string | opsional |
| nomor_telepon | string | opsional; simpan sebagai teks |
| is_active | boolean | default true |
| created_at | datetime | audit |
| updated_at | datetime | audit |

Siswa dibuat oleh kepala sekolah dan/atau wali kelas sesuai PRD: kepala sekolah dapat mengelola data siswa dan menentukan penugasannya; wali kelas dapat mengelola siswa hanya pada kelas/tahun ajaran yang ditugaskan. Siswa pada periode berbeda diperlakukan sebagai rekaman periode yang berbeda agar histori rapor tidak berubah ketika naik kelas. NIS/NISN boleh mengidentifikasi orang yang sama, tetapi rekaman siswa periode tetap memiliki ID berbeda. Hindari menyalin data otomatis antarperiode pada MVP.

### 3.5 Sheet `mata_pelajaran`
| Kolom | Tipe/logika | Aturan |
|---|---|---|
| id | string | PK |
| wali_kelas_id | string | FK penugasan |
| kode_mata_pelajaran | string | wajib; unik dalam penugasan |
| mata_pelajaran | string | wajib |
| is_active | boolean | default true |
| created_at | datetime | audit |
| updated_at | datetime | audit |

Mata pelajaran ditetapkan kepala sekolah atau dikelola wali kelas dalam penugasannya. Mata pelajaran pada kelas/periode berbeda merupakan data terpisah. Tidak boleh menghapus mata pelajaran yang sudah memiliki nilai; nonaktifkan atau tolak penghapusan.

### 3.6 Sheet `nilai_mata_pelajaran`
| Kolom | Tipe/logika | Aturan |
|---|---|---|
| id | string | PK |
| siswa_id | string | FK siswa |
| mata_pelajaran_id | string | FK mata pelajaran |
| nilai_tugas_1 | number | opsional, 0–100 |
| nilai_tugas_2 | number | opsional, 0–100 |
| nilai_tugas_3 | number | opsional, 0–100 |
| nilai_tugas_4 | number | opsional, 0–100 |
| nilai_uts | number | opsional, 0–100 |
| nilai_uas | number | opsional, 0–100 |
| nilai_akhir | number | hasil kalkulasi backend; kosong jika belum lengkap |
| is_complete | boolean | menandai komponen wajib lengkap |
| created_at | datetime | audit |
| updated_at | datetime | audit |

Kunci logis unik: `siswa_id + mata_pelajaran_id`. Validasi bahwa siswa dan mapel terhubung ke `wali_kelas` penugasan yang sama. Komponen tugas yang kosong tidak otomatis dianggap nol. Untuk MVP, jika semua empat tugas merupakan komponen wajib, nilai akhir baru dihitung saat tugas 1–4, UTS, dan UAS terisi. Jika sekolah ingin komponen tugas opsional, perubahan aturan harus disetujui dahulu.

Rumus:
`rata_tugas = (nilai_tugas_1 + nilai_tugas_2 + nilai_tugas_3 + nilai_tugas_4) / 4`
`nilai_akhir = (rata_tugas × bobot_tugas + nilai_uts × bobot_uts + nilai_uas × bobot_uas) / 100`
Bobot disimpan sebagai persentase dan total wajib 100. Nilai akhir dibulatkan konsisten ke dua angka desimal untuk tampilan/perhitungan.

### 3.7 Sheet `nilai_sikap`
| Kolom | Tipe/logika | Aturan |
|---|---|---|
| id | string | PK |
| siswa_id | string | FK siswa |
| predikat | string/enum | sesuai opsi sekolah; validasi dengan rentang/predikat rapor |
| deskripsi | string | deskripsi sikap |
| created_at | datetime | audit |
| updated_at | datetime | audit |

Kunci logis unik: satu catatan sikap per siswa-periode. Karena `siswa` sudah terkait ke penugasan/periode, tidak perlu menambah `tahun_ajaran_id` di tabel ini.

### 3.8 Sheet `rekap_kehadiran`
| Kolom | Tipe/logika | Aturan |
|---|---|---|
| id | string | PK |
| siswa_id | string | FK siswa |
| jumlah_hadir | number | bilangan bulat >= 0 |
| jumlah_sakit | number | bilangan bulat >= 0 |
| jumlah_izin | number | bilangan bulat >= 0 |
| jumlah_alpha | number | bilangan bulat >= 0 |
| keterangan | string | opsional |
| created_at | datetime | audit |
| updated_at | datetime | audit |

Kunci logis unik: satu rekap per siswa-periode. Ini adalah rekap jumlah, bukan absensi harian. Jangan membangun absensi harian dalam MVP karena tidak diminta.

### 3.9 Sheet `pengumuman`
| Kolom | Tipe/logika | Aturan |
|---|---|---|
| id | string | PK |
| judul | string | wajib |
| isi | string | wajib |
| dibuat_oleh | string | FK `user.id` kepala sekolah |
| created_at | datetime | audit |
| updated_at | datetime | audit |

Semua wali kelas dapat melihat pengumuman aktif/tersimpan. MVP tidak memerlukan status baca per user, lampiran, atau pengiriman email.

### 3.10 Sheet `pengaturan_rapor`
| Kolom | Tipe/logika | Aturan |
|---|---|---|
| id | string | PK |
| tahun_ajaran_id | string | FK periode |
| wali_kelas_id | string | FK penugasan |
| bobot_tugas | number | 0–100 |
| bobot_uts | number | 0–100 |
| bobot_uas | number | 0–100 |
| predikat | string | JSON string berisi daftar rentang, contoh di bawah |
| created_at | datetime | audit |
| updated_at | datetime | audit |

Kunci logis unik: `tahun_ajaran_id + wali_kelas_id`. Bobot wajib berjumlah 100. Format `predikat` yang disarankan:
`[{"label":"A","min":90,"max":100},{"label":"B","min":80,"max":89.99},{"label":"C","min":70,"max":79.99},{"label":"D","min":0,"max":69.99}]`
Ini hanya nilai awal contoh; UI harus mengizinkan pengaturan rentang. Validasi tidak boleh ada overlap/celah pada skala 0–100. Rentang dapat ditampilkan dengan presisi dua desimal.

### 3.11 Sheet `pengaturan`
| Kolom | Tipe/logika | Aturan |
|---|---|---|
| id | string | PK |
| logo_sekolah | string | ID/referensi file Drive, opsional |
| nama_sekolah | string | wajib setelah setup awal |
| nama_kepala_sekolah | string | opsional |
| nip_kepala_sekolah | string | opsional |
| updated_by | string | FK user bila sudah tersedia |
| created_at | datetime | audit |
| updated_at | datetime | audit |

Untuk MVP hanya satu baris pengaturan global yang digunakan. Setup tidak boleh menambahkan baris pengaturan duplikat saat dijalankan ulang.

## 4. Indeks logis / constraint yang wajib divalidasi backend
Google Sheets tidak menyediakan foreign key atau unique constraint database seperti SQL; semua constraint berikut harus diperiksa pada server sebelum menyimpan:
- `user.username` unik setelah normalisasi.
- `user.nip` unik bila tidak kosong.
- `tahun_ajaran.tahun_ajaran + semester` unik.
- Maksimal satu `tahun_ajaran.is_active = true`.
- `wali_kelas.tahun_ajaran_id + kelas` unik.
- `siswa.wali_kelas_id + no_absen` unik.
- `mata_pelajaran.wali_kelas_id + kode_mata_pelajaran` unik.
- `nilai_mata_pelajaran.siswa_id + mata_pelajaran_id` unik.
- Satu `nilai_sikap` dan satu `rekap_kehadiran` per siswa.
- Satu `pengaturan_rapor` per periode/penugasan.
- Semua foreign key harus menunjuk ID yang ada.
- Siswa dan mata pelajaran pada catatan nilai harus berasal dari penugasan yang sama.
- Pengguna nonaktif tidak bisa login; wali kelas hanya dapat mengakses penugasan miliknya.
- Gunakan `LockService` untuk operasi create/update yang memeriksa keunikan.

## 5. Batasan data dan performa
- Lakukan pembacaan range secara batch dan tulis dalam batch.
- Simpan tanggal, boolean, angka, dan string secara konsisten; validasi saat membaca karena data Spreadsheet dapat diedit manual.
- Hindari menyimpan objek besar atau foto langsung di sel.
- MVP belum memerlukan log audit lengkap, import/export massal, absensi harian, notifikasi email, multi-sekolah, atau integrasi eksternal.
