# Architecture — Sistem Absensi & Penilaian Siswa SD (Versi 2)

## 1. Tujuan dan batasan arsitektur
Aplikasi web internal sekolah untuk mengelola data tahun ajaran, penugasan wali kelas, siswa, mata pelajaran, nilai, rekap kehadiran, rapor, pengumuman, dan pengaturan sekolah. Kepala sekolah menjadi pengelola utama dan menentukan wali kelas, kelas, tahun ajaran, serta data siswa dan mata pelajaran sesuai cakupan kewenangannya.

Prioritas: MVP yang stabil, mudah dirawat, responsif, dan cepat dikerjakan. Ikuti dokumen `.prd.md`, `.database.md`, dan `.tasks.md`; jangan menambah modul di luar dokumen tanpa persetujuan pengguna.

## 2. Stack dan batasan platform
- Backend: Google Apps Script (V8 runtime).
- Frontend: HTML, CSS, JavaScript vanilla; Tailwind CSS untuk styling UI.
- Penyimpanan utama: Google Spreadsheet yang diakses melalui `SpreadsheetApp`.
- File gambar/logo: Google Drive, dengan konfigurasi ID folder/file yang jelas.
- Deployment: Apps Script Web App.
- File utama minimum: `index.html`, `code.gs`, `setup.gs`. Boleh membuat file `.gs`/`.html` tambahan bila benar-benar membantu pemisahan tanggung jawab dan tetap kompatibel dengan Apps Script.
- Jangan memakai Laravel, Node.js server, SQL server, bundler, atau framework frontend tambahan.
- Tailwind CDN boleh digunakan untuk MVP; jangan mengasumsikan proses build Tailwind.
- Jangan pernah menyimpan password mentah. Simpan hash password dengan salt/strategi yang didukung Apps Script dan dokumentasikan keterbatasan keamanan autentikasi custom. Jangan mengandalkan password yang ditulis langsung di Spreadsheet sebagai teks biasa.

## 3. Struktur komponen yang disarankan
- `index.html`: shell aplikasi, login, layout, navigasi, komponen UI, dialog/modal, tabel, dan pemanggilan `google.script.run`.
- `code.gs`: `doGet`, autentikasi dan sesi, otorisasi server-side, validasi input, operasi bisnis, akses Spreadsheet, dan endpoint yang dipanggil frontend.
- `setup.gs`: membuat/memvalidasi struktur Spreadsheet dan header, menyiapkan pengaturan awal yang aman, serta menampilkan ringkasan hasil setup.
- File tambahan opsional:
  - `auth.gs`: login, logout, validasi sesi, pemeriksaan role.
  - `repositories.gs`: helper baca/tulis Spreadsheet.
  - `services.gs`: aturan nilai, ranking, tahun ajaran, dan rekap.
  - `styles.html` / `scripts.html`: pemisahan aset frontend bila diperlukan.
  Tambahan file tidak boleh menjadi alasan membuat arsitektur terlalu rumit.

## 4. Prinsip arsitektur
1. Spreadsheet adalah penyimpanan data; setiap tabel direpresentasikan oleh satu sheet dengan nama dan header yang ditentukan di `.database.md`.
2. Gunakan ID unik stabil untuk relasi. Jangan memakai nomor baris sebagai foreign key.
3. Semua akses data dilakukan melalui fungsi backend; frontend tidak boleh menentukan sendiri izin akses.
4. Semua fungsi mutasi memvalidasi sesi, role, cakupan tahun ajaran/penugasan, dan input di server.
5. Data ditampilkan sesuai role:
   - `kepala_sekolah`: akses administratif seluruh sekolah.
   - `wali_kelas`: hanya data kelas/tahun ajaran yang ditugaskan kepadanya.
6. Gunakan `LockService` pada operasi yang rentan bentrok seperti pembuatan ID/penyimpanan berurutan.
7. Hindari membaca Spreadsheet berkali-kali per sel. Ambil data dalam batch, proses di memori, lalu tulis batch.
8. Tampilkan pesan sukses/gagal yang jelas; detail teknis dicatat di log tanpa membocorkan password/token.
9. Gunakan konfirmasi sebelum penghapusan. Untuk data yang telah memiliki relasi/riwayat, utamakan penonaktifan atau cegah penghapusan daripada merusak histori.
10. UI modern dan sederhana: sidebar/nav yang jelas, kartu ringkasan, tabel responsif, modal yang konsisten, loading state, empty state, dan notifikasi.

## 5. Autentikasi dan sesi
- Login menggunakan `username` dan `password`; tidak ada registrasi publik.
- Role hanya `kepala_sekolah` dan `wali_kelas`.
- Pengguna yang belum ditugaskan sebagai wali kelas tidak boleh memperoleh akses halaman wali kelas.
- Validasi role wajib dilakukan pada setiap fungsi backend yang sensitif, bukan hanya menyembunyikan menu frontend.
- Simpan sesi dengan token acak berumur terbatas menggunakan mekanisme server-side yang sesuai untuk Apps Script; jangan mempercayai role/user ID yang dikirim browser tanpa validasi token.
- Logout mengakhiri sesi.
- Update `terakhir_login` setelah login berhasil.
- Buat akun kepala sekolah awal melalui langkah inisialisasi yang eksplisit dan aman, bukan kredensial default permanen yang tersebar dalam kode. Jika mekanisme password hashing tidak memadai untuk produksi, dokumentasikan sebagai batasan dan jangan menyebutnya setara dengan sistem identitas enterprise.

## 6. Aturan tahun ajaran dan penugasan
- Satu tahun ajaran memiliki `tahun_ajaran`, `semester`, tanggal mulai/selesai, dan status aktif.
- Hanya satu periode boleh aktif pada satu waktu; validasi di server.
- Kepala sekolah menetapkan user wali kelas untuk satu kelas pada satu tahun ajaran/semester.
- Kelas yang tersedia: `1`, `2`, `3`, `4`, `5`, `6`; tidak ada kelas paralel.
- Penugasan historis tidak boleh dihapus jika telah mempunyai data siswa/nilai/kehadiran. Tampilkan sebagai riwayat baca-saja setelah periode selesai.
- Siswa, mata pelajaran, nilai, rekap kehadiran, dan pengaturan rapor harus terikat ke konteks penugasan/tahun ajaran yang benar, baik secara langsung maupun melalui relasi wali kelas.

## 7. Aturan nilai dan ranking
- Bobot tugas, UTS, dan UAS disimpan per tahun ajaran/penugasan; total bobot harus 100%.
- Nilai akhir mata pelajaran = rata-rata nilai tugas yang terisi × bobot tugas + nilai UTS × bobot UTS + nilai UAS × bobot UAS. Bobot dinyatakan sebagai persentase dan dibagi 100. Jika belum semua komponen wajib diisi, status nilai adalah belum lengkap dan jangan mengarang nilai 0 untuk komponen kosong.
- Jumlah nilai akhir seluruh mata pelajaran yang lengkap menjadi dasar nilai agregat/ranking siswa pada satu kelas dan satu periode. Untuk perbandingan yang adil, ranking memakai rata-rata nilai akhir mata pelajaran lengkap, bukan jumlah mentah, kecuali `.prd.md` kemudian secara eksplisit menyetujui aturan berbeda.
- Ranking sementara diberi label “sementara” jika ada siswa atau nilai mata pelajaran yang belum lengkap. Aturan tie: nilai agregat sama memperoleh ranking yang sama (competition ranking: 1, 2, 2, 4).
- Predikat ditentukan dari rentang nilai yang dikonfigurasi. Rentang tidak boleh tumpang tindih atau menyisakan celah dalam skala 0–100.
- Perhitungan akhir dan ranking dilakukan di backend; frontend hanya menampilkan hasil.

## 8. Keamanan dan privasi
- Batasi akses siswa berdasarkan penugasan wali kelas yang sedang dipilih.
- Validasi tipe, panjang, format, rentang nilai, tanggal, enum, dan relasi ID pada server.
- Escape teks pengguna saat ditampilkan untuk mencegah injeksi HTML.
- Jangan menyisipkan data sensitif ke HTML secara langsung atau menampilkan stack trace kepada pengguna.
- Jangan menganggap ID Spreadsheet/Drive sebagai mekanisme otorisasi.
- Foto pengguna/logo sekolah disimpan di Drive dengan akses yang dibatasi; simpan ID/referensi file di Spreadsheet, bukan data gambar besar di sel.
- Jangan menghapus/menimpa data lama saat setup dijalankan ulang.
- Gunakan `PropertiesService` untuk konfigurasi ID Spreadsheet/folder jika sesuai, bukan menanamkan rahasia pada frontend.

## 9. Standar UI dan UX
- Bahasa antarmuka: Bahasa Indonesia.
- Gaya: modern, sederhana, rapi, nyaman untuk penggunaan desktop dan tetap responsif di tablet/ponsel.
- Login menampilkan logo, nama sekolah, nama sistem, username, password, tombol login.
- Navigasi dan menu berbeda berdasarkan role.
- Form memakai label, validasi, indikator wajib, dan pesan kesalahan yang jelas.
- Modal tambah/edit/detail, dialog konfirmasi hapus, pencarian, filter, sorting, dan status loading sesuai kebutuhan halaman.
- Aksesibilitas dasar: kontras memadai, fokus keyboard, label input, dan tombol dengan nama yang jelas.

## 10. Integrasi frontend-backend
- Gunakan wrapper Promise untuk `google.script.run` agar alur async konsisten.
- Semua endpoint mengembalikan format konsisten, misalnya `{ success: true, data: ..., message: "..." }`; error ditangani tanpa membocorkan detail internal.
- Hindari mengirim seluruh database ke browser. Endpoint hanya mengembalikan data yang diperlukan untuk halaman aktif.
- Gunakan pagination atau pembatasan data jika tabel mulai besar; untuk MVP, minimal gunakan batch read dan filter server-side.

## 11. Kriteria selesai arsitektur
Implementasi memenuhi dokumen ini bila:
- bisa dijalankan sebagai Apps Script Web App;
- setup Spreadsheet idempotent dan tidak merusak data;
- autentikasi serta otorisasi diperiksa di backend;
- role dan penugasan membatasi akses data;
- perhitungan nilai, predikat, dan ranking dilakukan secara konsisten;
- tidak ada modul tambahan yang belum disetujui.
